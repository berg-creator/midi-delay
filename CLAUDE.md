# MIDI Delay — правила работы в этом репозитории

## Язык
Всё общение с пользователем — **на русском**. Комментарии в коде и коммиты — тоже на русском.
Имена идентификаторов — английские, как принято в C++/JUCE.

## Что это за проект
Аудио-плагин VST3/AU: **MIDI-Driven Pitch Delay**. Дилей, чьи хвосты транспонируются
под приходящие MIDI-ноты. Целевая DAW — FL Studio.
Полный разбор: [docs/ANALYSIS.md](docs/ANALYSIS.md). План: [docs/ROADMAP.md](docs/ROADMAP.md).
Задачи: [docs/ISSUES.md](docs/ISSUES.md).

## Эстафета промптов — главное правило

Работа ведётся короткими сессиями по 1–3 задачи, чтобы не жечь контекст.
**Каждая сессия обязана закончиться так:**

1. Отработанный `prompts/NEXT.md` переместить в `prompts/archive/SNN-краткое-имя.md`.
2. Написать новый `prompts/NEXT.md` для следующей сессии по шаблону
   [prompts/_TEMPLATE.md](prompts/_TEMPLATE.md).
3. Отметить сделанное в `prompts/PROGRESS.md` — одна строка на задачу.

Это правило **рекурсивное**: сессия, которая работает по `NEXT.md`, тоже пишет следующий
`NEXT.md`. Так до конца M5. Если работа завершена полностью — вместо промпта написать
в `NEXT.md` строку «Работа по MVP завершена» и перечислить, что осталось из Post-MVP.

Промпт для следующей сессии должен быть **самодостаточным**: новая сессия не читает историю,
только `CLAUDE.md`, `prompts/NEXT.md` и явно перечисленные в нём файлы. Не пересказывай в промпте
то, что уже написано в `docs/` — дай ссылку и номер раздела.

## Технические инварианты (нарушать нельзя без ADR)

- В `processBlock` — ноль аллокаций, локов, логов, исключений. `ScopedNoDenormals`.
- MIDI обрабатывается **с sample offset**, а не пачкой в начале блока.
- Feedback берётся **до** питч-стадии — иначе высота хвостов кумулятивно уползает.
- Латентность питчера прячется в delay time, плагин репортит **нулевую** задержку.
  Подробности: [docs/ANALYSIS.md](docs/ANALYSIS.md) §5.
- Кроссфейды — **equal-power**, не линейные.
- `NEEDS_MIDI_INPUT TRUE` в CMake — без него FL Studio не покажет MIDI-вход.
- Каждая нетривиальная DSP-единица оставляет один запускаемый офлайн-тест. Без фреймворков.

## Среда разработки
macOS 26, arm64, clang 21, cmake 4.4, gh 2.96.
**Полного Xcode нет — только Command Line Tools.** Это может помешать AU-таргету,
подписи и нотаризации (задачи #2 и #33). Проверять, а не предполагать.

## Стиль
Ponytail: самое простое решение, которое действительно работает. Не строить абстракций
под будущее, которого может не быть. Но: валидацию входа, обработку ошибок и анти-клик
не упрощать никогда — это то, что слышно в миксе.
