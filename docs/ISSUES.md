## [7] Кольцевой буфер задержки
**Labels:** dsp
**Milestone:** M1

## [17] Компенсация латентности: прячем алгоритм в delay time
**Labels:** dsp, architecture
**Milestone:** M2

### Описание
Ключевое из `docs/ANALYSIS.md` §5. Внутренняя латентность питчера вычитается из позиции
чтения: `readOffset = delayTime − algLatency`. Минимальный delay time равен `algLatency`.
`setLatencySamples(0)`, пока условие выполняется.

**Нижний предел зависит от движка (сессия 09, [ADR 0005](adr/0005-hq-pitch-engine.md)):**
у Fast это 5762 сэмпла (120 мс при 48 кГц), у HQ — 8640 (180 мс). Значит кламп
не константа, а функция активного значения Quality, и при переключении на HQ
уже выставленное короткое время надо подтягивать вверх — молча или с показом
в UI, но не оставлять как есть: сейчас смещение просто упирается в кламп
`Voice::setDelaySamples`, и хвост приходит позже заказанного.

### Критерии приёмки
- [ ] Плагин репортит нулевую латентность при delayTime ≥ algLatency
- [ ] Реальная задержка хвоста измерена и совпадает с выставленной (±1 мс)
- [ ] Минимальный delay time ограничен снизу и это видно в UI
- [ ] Предел пересчитывается при смене Quality, а не зашит константой
- [ ] Смена алгоритма питчинга не требует правок в вызывающем коде

## [21] Feedback без кумулятивного питч-дрейфа
**Labels:** dsp
**Milestone:** M3

### Описание
Feedback берётся **до** питч-стадии: в буфер возвращается чистый сигнал. Иначе каждый круг
транспонирует хвост заново и подклад уползает по высоте (эффект Шепарда). Опционально —
переключатель Pitched Feedback для тех, кому этот уползающий эффект нужен как приём.

### Критерии приёмки
- [ ] При feedback > 0 высота повторов не уползает
- [ ] Feedback = 1.0 не даёт самовозбуждения (ограничение или мягкий сатуратор в петле)
- [ ] Переключатель Pitched Feedback (если сделан) документирован как спецэффект
- [ ] Хвост затухает предсказуемо и полностью

## [24] Ограничение диапазона питча и защита от «бурундука»
**Labels:** dsp
**Milestone:** M3

### Описание
Параметр Pitch Range ограничивает сдвиг. За границей — либо clamp, либо октавный перенос
внутрь диапазона. Опция Formant Hold в MVP не реализуется, но интерфейс не должен ей мешать.

## [41] Лицензирование: триал, ключи, защита от копирования
**Labels:** release, post-mvp
**Milestone:** Post-MVP

### Описание
Плагин платный ($10–25) с бесплатным триалом на 7 дней. По истечении триала без
валидного ключа плагин глушит выход.

Трезвая рамка: бинарник живёт на машине пользователя, снять проверку дизассемблером
может кто угодно. Цель не «невозможно украсть», а «заплатить проще, чем искать кряк» —
ровно то, чем ограничиваются iZotope и Waves.

Схема без своего сервера:
- **Триал.** Дата первого запуска пишется в файл настроек и дублируется в системное
  хранилище (Keychain на macOS, реестр на Windows), привязка к machine ID — иначе
  триал сбрасывается переустановкой.
- **Ключ.** Файл, подписанный Ed25519: внутри email покупателя и machine ID,
  публичный ключ зашит в бинарник. Проверка офлайн, серверная инфраструктура не нужна.
- **Продажа.** Gumroad или Lemon Squeezy — деньги, письма и налоги на их стороне,
  ключ генерит их вебхук. Свой биллинг не писать.
- **Watermark.** Имя покупателя из ключа показывается в окне About. Против расшаривания
  это работает лучше криптографии: файл со своим именем никто не выкладывает.

Ветвление по лицензии должно жить **вне** `processBlock` — флаг читается атомарно,
проверка ключа и работа с файлами только в GUI-потоке.

### Критерии приёмки
- [ ] Первый запуск заводит триал, оставшиеся дни видны в окне плагина
- [ ] По истечении триала без ключа выход глушится, плагин не падает и не молчит незаметно
- [ ] Переустановка плагина триал не сбрасывает
- [ ] Валидный ключ снимает ограничение, невалидный отвергается с внятным сообщением
- [ ] Проверка лицензии не делает аллокаций и ветвлений в аудиопотоке
- [ ] Покупка через Gumroad/Lemon Squeezy сквозняком: оплата → письмо → ключ → работает
- [ ] Имя покупателя видно в About
