# ADR 0003. Кроссфейд обхода — линейный, а не equal-power

**Статус:** принято, 2026-09-09
**Задача:** [#11](../ISSUES.md), веха M1
**Контекст:** инвариант «кроссфейды — equal-power» в [CLAUDE.md](../../CLAUDE.md)

## Решение

Переход между обработанным сигналом и dry при включении bypass — **линейный**:

```cpp
out = processed * wetPath + dry * (1 - wetPath);   // wetPath: 1 -> 0 за 20 мс
```

Инвариант из `CLAUDE.md` требует equal-power. Здесь он не применяется, и это осознанно.

## Почему

Equal-power (`sqrt(a)` и `sqrt(1-a)`) держит постоянной **сумму мощностей** и правилен
для **некоррелированных** сигналов: склейка двух ридеров varispeed, увод уворованного
голоса, стык гранул. Там линейный кроссфейд проваливает громкость в середине на 3 dB.

Dry и processed — сигналы **коррелированные**: processed это тот же dry плюс хвост,
а при `mix = 0` — буквально он же. Equal-power на коррелированных сигналах даёт
обратную ошибку: в середине перехода `sqrt(0.5) + sqrt(0.5) = 1.41`, то есть **горб
+3 dB**. При `mix = 0` обход бесшумного плагина громко квакнул бы — ровно тот щелчок,
ради устранения которого кроссфейд и заводился.

Второе, столь же важное: линейная форма сохраняет **бит-в-бит**. При `wetPath = 1`
остаётся ровно `processed`, при `wetPath = 0` — ровно `dry`, без домножения на
`sqrt(1.0)`, которое в float не всегда единица.

## Границы решения

Правило остаётся прежним: **equal-power там, где склеиваются некоррелированные
сигналы** — это #14 (varispeed), #16 (кража голоса) и всё, что придёт после.
Линейный кроссфейд разрешён только для пары dry / processed, то есть для bypass.

Проверяется тестом `Source/test_processor.cpp`, раздел 4: вход в обход и возврат
при wet в противофазе к dry, максимальный шаг между соседними сэмплами < 0,1.
