## Что выяснилось по ходу

- **JUCE 9.0.2**, а не 8.x — на старте проекта это актуальный мажор.
  API `juce_add_plugin` совместим, миграция не потребовалась.
- **AU обязан быть `aumf`, а не `aufx`.** `auval` прямо предупреждает: эффект принимает
  MIDI, но объявлен типом без MIDI. С `aufx` Logic не даст роутить ноты на плагин.
- **Полный Xcode не нужен** для сборки и валидации — Command Line Tools хватает.
  Под вопросом осталась только подпись и нотаризация (#33).
- Первая сборка JUCE занимает ~5 минут, инкрементальная — секунды. Но смена параметров
  `juce_add_plugin` (например `AU_MAIN_TYPE`) перегенерирует defines и пересобирает всё.

## Находки из проверки в FL Studio 20 (macOS)

- **FL сканирует только `/Library/Audio/Plug-Ins/VST3`, пользовательский
  `~/Library/Audio/Plug-Ins/VST3` — нет.** Проверено по базе плагинов FL: все 25
  найденных VST3 из системного каталога, ни одного из пользовательского.
  JUCE с `COPY_PLUGIN_AFTER_BUILD` ставит именно в пользовательский, поэтому плагин
  в FL не появляется, хотя собран правильно. Лечится добавлением пути в
  Options → Manage plugins. Обязательно в документацию #32 — на это напорется каждый.
- AU при этом подхватывается сразу: FL сканирует `~/Library/Audio/Plug-Ins/Components`.
- FL держит загруженную библиотеку в памяти: после пересборки нужен «Reload plugin»
  в настройках обёртки, иначе видно старую версию.
- Кириллица в `juce::String` из обычного литерала рассыпается в мохибейку прямо в окне
  плагина. Тексты UI — только ASCII.

## Находки сессии 02 (ADR)

- **Rubber Band для нас закрыт.** Проверено по первоисточнику 2026-09-08: GPLv2+ либо
  платная коммерческая лицензия, £590 с обязательной атрибуцией и до £9320 без неё,
  плюс прямой запрет на раздачу через Apple App Store без покупки.
  **Signalsmith Stretch — MIT**, header-only, C++11: годится для закрытого продукта даром.
  Значит HQ-режим целится в Signalsmith, и MVP остаётся без единой сторонней DSP-зависимости.
- **Интерфейс `PitchShifter` обязан быть потоковым** (`process(in, out, n)`), а не «читай
  сам из общего буфера». Второй вариант короче и не требует лишней памяти, но в него
  не влезает Signalsmith — а вся абстракция затевалась ровно ради него. Цена честного
  интерфейса — свой кольцевой буфер длиной в окно внутри каждого питчера, ~15 КБ на голос.
- **Латентность питчера обязана быть константой.** Она вычитается из позиции чтения один
  раз в `prepare`; движок, меняющий её на ходу, заставил бы дёргать `setLatencySamples`
  из аудиопотока. Записано инвариантом в ADR 0002.
- **У varispeed фактическая задержка гуляет в пределах полуокна** (до ~40 мс) — это
  природа алгоритма, а не баг. На старт ноты не влияет: ноту открывает огибающая, она
  сэмпл-в-сэмпл по MIDI. Слушать на #19.
- **Заголовки в `Source/DSP/` намеренно без JUCE** — только stdlib и `float* const*`.
  Офлайн-тесты из #7, #14, #19 собираются одной командой clang, без линковки с фреймворком.

## Находки сессии 03 (CI)

- **Имя генератора Visual Studio задавать нельзя.** `-G "Visual Studio 17 2022"` на
  `windows-latest` падает с «could not find any instance of Visual Studio»: версия студии
  едет вместе с образом раннера. На Windows генератор не указываем вовсе — дефолтный
  генератор CMake находит установленную. На macOS остаётся Ninja: она сама cl.exe
  не найдёт, а на маке ничего не ищет.
- **Форматы по платформам разводить не нужно.** JUCE отбрасывает AU на не-Apple сама,
  в `_juce_get_platform_plugin_kinds` (`JUCEModuleSupport.cmake`). Один общий список
  `FORMATS VST3 AU Standalone` работает и на Windows — AU просто не создаётся.
- **`COPY_PLUGIN_AFTER_BUILD` в CI выключён** опцией `MIDIDELAY_COPY_PLUGIN=OFF`.
  Локально по-прежнему копирует, значение по умолчанию ON.
- **pluginval strictness 10 проходит за минуту**, тесты GUI на раннере не падают —
  `--skip-gui-tests` не понадобился.
- **AU в CI не валидируется, и это осознанное решение.** На чистом раннере AU надо
  сперва зарегистрировать в системе и прогреть кэш компонентов; возни больше, чем пользы.
  AU проверяется локально: `auval -v aumf Mdly Mkev`, он зелёный. Если когда-нибудь
  понадобится AU в CI — это отдельная задача, а не строчка в workflow.
- **Защита ветки `main`:** обязательные проверки `macOS` и `Windows`, `strict: false`
  (не требовать свежести ветки — на соло-проекте это только заставляло бы ребейзить),
  `enforce_admins: false` — иначе владелец не смог бы пушить в `main` напрямую, а вся
  работа сессиями идёт именно так. Красный прогон блокирует merge PR. Проверено, что
  настройка выставлена; сквозным PR с красной сборкой не проверялось.
- **`actions/checkout@v4` и `upload-artifact@v4` устарели** — тянут Node 20, раннеры
  ругаются. Актуальные — v7.
- **Сборка macOS дороже Windows примерно вдвое** из-за universal binary: ~5 минут
  против ~2,5. Кэш компиляции не заводили: на публичном репозитории минуты бесплатны,
  а `ccache` — лишняя движущаяся часть. Появится, если время прогона станет мешать.
